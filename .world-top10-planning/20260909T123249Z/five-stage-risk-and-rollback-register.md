# 5단계 위험·복구 등록부

| ID | 위험/발생 신호 | 예방 | 중단 기준 | 안전한 복구 |
|---|---|---|---|---|
| RISK-001 | 검증 식당 수 감소 | 전후 레코드 수·해시 비교 | 승인 수가 이전보다 감소 | 이전 데이터 복사본 복원 |
| RISK-002 | 비공식 출처가 공식으로 표시 | `officialUrl`·`isVerified` 검사 | 출처 등급 A가 아님 | 해당 레코드 격리 |
| RISK-003 | 공유 링크가 자동 저장 | 미리보기 후 확인 계약 | 확인 전 `persist` 호출 | state 백업 복원, 기능 플래그 격리 |
| RISK-004 | 인증 토큰 노출 | HttpOnly 세션·민감 경로 캐시 금지 | localStorage·로그에 토큰 | 인증 설정 비활성 유지 |
| RISK-005 | 캐시 구판 표시 | 판번호·manifest 지문 | public/app 버전 불일치 | 이전 shell 유지 후 재배포 |
| RISK-006 | 성능 예산 초과 | Lighthouse/CWV 기준선 | LCP·CLS·TBT 임계치 초과 | bundle·광고 변경 되돌림 |
| RISK-007 | 법적·광고 오인 | 라벨·동의·검토 문서 | 승인 없는 송출·법적 완료 표시 | 관련 표시를 미검증으로 강등 |
| RISK-008 | 기기 시험 판 불일치 | 시험 전 공개 버전 고정 | 기기 판≠공개 판 | 시험 무효화 후 재시험 |
| RISK-009 | Pages 배포 부분 성공 | artifact manifest·HEAD 확인 | 핵심 URL 200 미충족 | 마지막 통과 artifact 유지 |
| RISK-010 | 운영 복구 실패 | dry-run·연락망·SLA | 담당자·복구 명령 없음 | `public-development` 유지 |

복구 순서: (1) 공개 상태를 `public-development`로 유지, (2) 실패한 artifact·데이터를 격리, (3) 마지막 통과 복사본 해시 확인, (4) 해당 파일만 복원, (5) 자동 시험 재실행, (6) 원인·영향·증거를 기록, (7) 외부 담당자에게 재개 조건 전달. `git reset --hard`, 강제 push, 광범위 삭제, B드라이브 접근은 사용하지 않는다.

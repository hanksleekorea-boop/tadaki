# STAGE-2-FOUNDATION

1. 목표: 데이터·권한·공통 상태 기반을 시험 가능하게 한다.
2. 완료 모습: import/export·삭제·복원이 안전하게 동작한다.
3. 범위: 스키마·로컬 저장·OAuth discovery.
4. 제외: 실제 OAuth 토큰·원격 동기화 활성.
5. 진입: STAGE-1 증거.
6. 입력: 승인 레코드·기준선 지문.
7. 산출물: 스키마·계약·시험 로그.
8. ID: GAP-004, REQ-004.
9. 순서: 스키마→검증→복원.
10. 병렬: 문서 검사·JSON 경계.
11. 순차: 제공자 확인 후 계정.
12. 변경 위치: `apps/web`, `sync.js`.
13. 계약: UTF-8 JSON·버전·필드 보존.
14. 정상: 동일 파일 round-trip.
15. 빈/로딩: 빈 자료·큰 파일 안내.
16. 실패/복구: 손상 거부·기존 보존.
17. 접근성/플랫폼: 키보드·모바일 입력.
18. 보안: 토큰 저장 금지·fail-closed.
19. 예산: 1MB JSON·5MB 암호 파일.
20. 자동 시험: parse/import/delete.
21. 수동 시험: 브라우저·보조기술.
22. 중단: 스키마 손상·권한 오구성.
23. 종료: 복원·삭제·권한 거부 증거.
24. 인계: STAGE-3에 공통 계약 전달.
